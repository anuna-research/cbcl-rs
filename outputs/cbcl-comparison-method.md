# Comparison method

## Scope

This is a bounded, source-led comparison of CBCL as a portable business-message, protocol and state kernel. It is not a search for a universal negative or a benchmark comparison. Worktree: `state-rules-spec`, inspected 2026-11-01; local baseline hashes are recorded alongside captures. The baseline includes uncommitted implementation and proof work. Specifications describe intent; a specification alone is not implementation evidence.

This is Tier 4 research documentation under anuna-dev: no normative language change, migration or new production API is introduced. Consequently no new SPEC or implementation plan is created. A fresh-context independent review checks comparison claims and scope.

## Assessment ratings

Six axes separate substrate neutrality, dynamic vocabulary, behavioral extensions, local causal conformance, authenticatable evidence and derived state. “Native” means explicitly supplied by the examined design at its stated scope; it does not mean identical semantics or equally strong guarantees. “Partial” means a narrower mechanism, profile-dependent support or important integration boundary. “External” means supplied by an application/host rather than the examined layer. “Excluded” means outside that layer's stated design or incompatible with the axis as defined. “Unknown” means insufficient inspected evidence. None of these is a universal impossibility claim.

Dynamic vocabulary means application-defined message types, schemas, performatives or callable interfaces within the system; it does not by itself require automatic remote schema acquisition. General executable contract, actor and validation extensions count as native behavior under this broad rubric, regardless of their restriction or substrate.

Substrate-neutral means no mandatory common ledger or particular application platform. Behavioral extension means executable/declarative behavior beyond field shapes, not necessarily a restricted or verified extension language. Local causal conformance means role-local checks over interaction history; workflow execution counts at its executor scope and is not equated with independently verifiable business authorization. Signed evidence means an authentication/canonical-evidence model; it does not imply external signing/key custody is built in. Derived state includes deterministic maps and room state, with the underlying event/map distinction preserved in the cases.

## Claim policy

The axes are explanatory, not a weighted leaderboard. A feature intersection designed around CBCL would not prove novelty. No full-bundle rule is asserted. Unknown is never turned into negative support. Elephant derives documented support only from native assessments and records that bounded search cannot establish universal uniqueness. Human-curated assessments are signed claims, not machine-verified proofs about the external projects.

Each matrix cell inherits its row's primary-source set and explanatory scope; it is not an independently pinpointed proof. Detailed case notes identify the decisive boundaries. Broad or controversial claims need narrower source inspection before publication as normative statements.

## Collection and reproducibility

Three ar-crawl sessions retain IDs, recordings and transcripts in the evidence directory. Failed browser navigation is preserved: W3C publication pages were blocked, so official editor copies were inspected and version-scoped. BSPL and ebBP PDF browser navigation failed; direct primary-origin downloads plus pdftotext supplied explicitly recorded fallbacks. No authenticated content was collected. This is purposive coverage, not a PRISMA-complete literature survey: no exhaustive database query, independent double coding, full citation closure or uniform full-paper review was performed. PACT remains an unscored lead.

The machine matrix, source catalog, SHA-256 baseline hashes, signed Elephant journal and reasoner outputs are reproducibility artifacts. Hashes attest captured bytes, not continuing accuracy of live sites. MCP is pinned to 2025-11-25; Arazzo 1.1.0, A2A 1.0.0, Matrix room version 7, WoT 2.0 editor draft and AS2 editor-copy scopes must accompany claims.
